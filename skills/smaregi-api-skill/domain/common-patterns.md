# 共通パターンと注意事項

## 純売上の集計パターン

正しいリクエスト:
```
GET /transactions?transaction_head_division=1&cancel_division=0&transaction_date_time_from=...&transaction_date_time_to=...
```

- ⚠️ 必ず `transaction_head_division=1`（通常取引）と `cancel_division=0`（取消されていない）の両方を指定すること

## 前月比較の正しいやり方

1. 今月分: `transaction_date_time_from=今月1日` / `transaction_date_time_to=今月末日`
2. 前月分: `transaction_date_time_from=前月1日` / `transaction_date_time_to=前月末日`
3. 両方の結果を比較

- ⚠️ 期間上限は31日間なので、1ヶ月単位なら1回のリクエストで取得可能

## 商品別売上ランキング

1. `with_details=all` で取引明細を取得
2. 明細の `productId` ごとに金額を集計
3. 金額降順でソート

- ⚠️ 取引件数が多い場合、レスポンスが非常に大きくなります
- ⚠️ 期間を短く（1日〜1週間）して取得することを推奨

## 期間分割の実装パターン

31日を超える期間のデータが必要な場合:
1. 開始日と終了日を受け取る
2. 31日ごとに分割
3. 各期間のリクエストを順次実行
4. 結果を結合

## 禁止パターン

- ⚠️ 全商品×全取引のクロス集計は禁止（レスポンスが巨大になりタイムアウトします）
- ⚠️ limit を指定せずに全件取得することは避けてください
- ⚠️ 1分間に100リクエスト以上の連続呼び出しは避けてください

## ページネーション

- `limit`: 1回のリクエストで取得する件数（最大1000）
- `offset`: 取得開始位置（0始まり）
- レスポンスヘッダの `X-Total-Count` で全件数を確認可能
- ⚠️ 全件が必要な場合は、offsetをlimitずつ増やしながら繰り返しリクエストしてください

## 日付フォーマット

- ISO 8601 形式: `2024-01-01T00:00:00+09:00`
- ⚠️ タイムゾーンは `+09:00`（日本時間）を指定してください
